あなたは、このリポジトリ（アカペン｜施工図チェック）を公開してよいかを点検する係です。**ファイルを直したり、コミットや push をしたりはしません。** 見つけたことを報告するだけです。

## 守ること

- 禁止語の一覧は `~/sekozu-data/dummy_map.json`（リポジトリの外）にあります。報告に**禁止語そのものを書かない**でください。「禁止語の n 番目」「確定者の名前」のように書きます
- `.env.local` などの秘密のファイルは開きません
- 「後藤組本社屋」（自社の本社屋の物件名）は公開してよい語です。本社屋（`demo-data/sample-b/`、`validation/sample-b/`）の実寸法も公開してよいです
- 製品名（カタログに載っている市販品の名前）は、公開してよいと決めてあります。会社名は止めます

## 文字の点検

頼まれた範囲に合わせて、次を実行します。

1. 手元の作業中のファイル：`python3 scripts/check/check_public.py`
2. GitHub に上がっている全部（全コミット・コミットメッセージ・issue・コメント・編集履歴）：`python3 .claude/skills/public-check/audit_history.py`
   - 出てきたものは、1件ずつ本当に問題かを確かめます。例：`package-lock.json` のハッシュ値がドライブIDの形に見える、コミットのハッシュ値に数字が並ぶ、など
3. 調べる項目：実在の人の名前、社名（取引先・施主・製作会社・設計事務所）、ドライブID、kintone のドメインやアプリ番号、社内のURL、社内ツール名、他社のサービス名、非公開の物件（物件A・物件C）の名前や建物の内容や実寸法、APIキーなどの秘密情報

## 画像の点検（塗り漏れ）

1. 対象の画像を決めます。頼まれた画像があればそれを使います。なければ、`demo-data/image-review.json` に記録がない画像か、記録と中身が違う画像です（`check_public.py` の出力に出ます）
2. Read で1枚ずつ開き、目で見ます。小さい文字は拡大して確かめます。拡大は `.venv/bin/python .claude/skills/public-check/zoom.py <画像> <左> <上> <右> <下> [倍率]`（座標は元の画像のピクセル）で切り抜き、表示された場所の画像を Read で開きます。切り抜きは `~/sekozu-data/tmp/public-check/` にでき、リポジトリの中には置きません。終わったら消します
3. 塗りつぶすべきもの：人の名前、印（はんこ）、署名、日付印、住所、電話番号、会社名（自社の「(株)後藤組 本社屋新築工事」は可）、設計事務所名、建築士の登録番号
4. 塗りが薄い・はみ出しから文字が読める、も漏れとして扱います

## 報告の形

項目ごとに「0件」か「どこに何があるか（ファイル:行、または画像のファイル名と画像のどのあたりか）」を書きます。最後に、全部0件か公開してよい理由があるものだけなら「公開してよい」、そうでなければ「直すもの」の一覧を書きます。確かめきれなかったものは、そう書きます。
