# 施工図チェックの検証

AI の指摘が、人の朱書きをどれだけ拾えているかを確かめる手順です。
採点する係（`finding-reviewer` サブエージェント）には、**どの方法で判定した結果かを伏せて**渡します。前の方法と今の方法を比べるとき、採点の手加減が入らないようにするためです。

## 使う材料

- **人の朱書き（正解）**：`validation/sample-b/human-compare.json`。本社屋の鉄骨図 2SL・3SL・RSL の梁伏図の30件です。AI の判定には見せていません
- **判定結果**：保存してある結果を使います
  - 判定のフォルダ：`~/sekozu-data/uploads/<ID>/`（画面からチェックした結果）
  - 固定の結果：`demo-data/sample-b/check-result.json`（前の方法で判定したもの）

**新しく判定を回すとお金がかかります（1枚 約1.4〜2.6ドル）。** この手順は保存済みの結果で採点します。新しく判定を回すときは、費用を見積もってから人に相談します。

## 手順

1. **比べる結果を選ぶ**：2SL・3SL・RSL の梁伏図を含む結果を選びます。判定のフォルダの `result.json` の `pages` の `title` で分かります
2. **伏せたファイルを作る**（置き場所はリポジトリの外。例：作業用の一時フォルダ）
   ```
   python3 .claude/skills/finding-check/blind.py <置き場所> <結果1> [<結果2> ...]
   ```
   `<置き場所>/blind/` に採点係に渡すファイルが、`<置き場所>/key.json` に対応表ができます。対応表は採点が終わるまで採点係に見せません
3. **採点を頼む**：`finding-reviewer` サブエージェントに、`<置き場所>/blind/` のファイルと、`<置き場所>/scores/` に書くことを伝えます。対応表の場所は伝えません
   - 頼み方の例：「`<置き場所>/blind/` の A-s02.json を human-s02.json と照らして採点し、`<置き場所>/scores/A-s02.json` に書いて」
4. **数える**
   ```
   python3 .claude/skills/finding-check/tally.py <置き場所>
   ```
   結果ごとに、人の朱書きの「一致・近い・なし」、図面から判断できる人の指摘のうち一致した数、AI の指摘のうち「人にない」数が出ます
5. **報告**：数字と、一致しなかった人の朱書きの中身を短く書きます。採点係の判断で迷うもの（「近い」など）は、人の朱書きの画像（`validation/sample-b/human/`）を開いて確かめます

## 数字の読み方

- **図面から判断できる人の指摘**：打ち合わせや製作上の判断ではなく、図面同士の照合で分かるはずの朱書きです。AI が拾うべきものです
- **人にない**：人の朱書きにないAIの指摘です。間違いとは限りません（人が見落とした可能性もあります）。正しいかどうかは、現場の担当者が確かめます
- 判定は1回ごとに結果が少し変わります。1回の結果だけで良い悪いを決めないでください
