# 公開前の点検

アカペンのリポジトリを公開する前に、外に出してはいけない情報が入っていないかを確かめる手順です。
**直すのは、点検の報告を人が読んで決めてから**です。この手順では、ファイルの書き換え、履歴の書き換え、push はしません。

## いつ使うか

- GitHub のリポジトリを public にする前
- 図面の画像、デモのデータ、README のスクリーンショットを足したあと
- issue やコミットメッセージに、社内の話を書いたかもしれないとき

## 点検する8つの項目

| # | 項目 | 例 |
|---|---|---|
| 1 | 実在の人の名前 | 社員、確定した担当者、設計者 |
| 2 | ドライブID、kintone のドメインやアプリ番号、社内システムのURL | |
| 3 | 社内ツール名、他社のサービス名 | |
| 4 | 取引先・施主・製作会社・設計事務所の名前 | 製品名から会社が分かるものも確かめる（市販品の製品名は公開してよいと決めてある） |
| 5 | 非公開の物件（物件A・物件C）の名前、建物の内容、実寸法 | |
| 6 | 一度コミットして消したファイル | 履歴に残っていれば、公開すると見える |
| 7 | APIキー、パスワード、トークンなどの秘密情報 | |
| 8 | 図面画像の塗りつぶしの漏れ | 会社名、担当者名、印、住所、電話番号 |

公開してよいもの：自社の本社屋（「後藤組本社屋」、実寸法、断面、符号）。

## 手順

1. **手元のファイルの点検**
   ```
   python3 scripts/check/check_public.py
   ```
   「問題 0 件」なら次へ。問題があれば、その一覧を報告に入れます。
2. **GitHub に上がっている全部の点検**（全コミット、コミットメッセージ、issue、コメント、編集履歴）
   ```
   python3 .claude/skills/public-check/audit_history.py
   ```
   禁止語は「禁止語の n 番目」のように番号で出ます（語そのものは画面に出しません）。
   出てきたものは、本当に問題かを1件ずつ確かめます（ハッシュ値がたまたま形に合っただけ、など）。
3. **GitHub の設定の確認**：ブランチは master だけか、PR・リリース・タグがないか（手順2の1行目に出ます）。Wiki・Pages・Discussions が切れているかは `gh repo view --json hasWikiEnabled,hasDiscussionsEnabled` で確かめます
4. **画像の点検**：`public-checker` サブエージェントに頼みます。画像が多いときは、フォルダごとに分けて2つ並行で頼むと早く終わります
   - 頼み方の例：「`demo-data/sample-b/design/` の画像の塗り漏れを点検して」
   - 目で確かめて問題がなかった画像は、`python3 scripts/check/review_images.py` で記録します（記録と違う画像は、コミットのときに止まります）
5. **報告**：8つの項目ごとに「0件」か「どこに何があるか」を書きます。全部0件か、公開してよい理由があるものだけになったら「公開してよい」と書きます

## 見つかったときの直し方（人が決めてから）

- 今の版のファイル：直してコミットします
- 履歴に残っているもの：`git filter-repo --replace-text` で全履歴から消し、force push します。**force push は必ず人の許可を取ってから**です。消す前に `git clone --mirror` で控えを取り、控えはリポジトリの外に置きます
- issue の編集履歴：GitHub の画面で、その版を「Delete revision」で消します（人の操作）
